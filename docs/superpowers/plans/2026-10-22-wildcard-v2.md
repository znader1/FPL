# Wildcard v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three structurally different wildcard squads (Aggressive / Balanced / Gems) built on the user's real selling-price budget, with a role-built bench, a recency-light score, and a per-player explanation, testable on a Vercel preview before merge.

**Architecture:** The existing greedy `optimizer.build_chip_squad` gains a preset dict that switches it into a two-stage build (XI by greedy on the horizon scalar, bench by role rules from a new `src/chip_bench.py`); with no preset it behaves exactly as today so `chip_advisor`, the squad picker and free hit are untouched. `projections.add_wildcard_scores` loses its form/ownership stacking and gains trend, injury-prior and position-aware upside terms, each emitted as a column so `lineup_builder` can explain them. A new `api/wildcard_router.py` route returns the three squads + core; `/recommendations` takes `wildcard_preset` and keeps driving one squad downstream. The frontend gets one new page `/app/wildcard` reusing `DraftPitch`.

**Tech Stack:** Python 3 / FastAPI / pandas / pytest (backend, `FPL/`); React 18 / TypeScript / Vite / vitest / TanStack Query (frontend, `fpl-decision-hub`). Fly.io dev app + Vercel preview for testing.

**Spec:** `FPL/docs/superpowers/specs/2026-10-22-wildcard-v2-design.md`

## Global Constraints

- Every new tunable lives in `src/config.py`, tagged `[untested]` / `[operational]` / `[flag]`; logic files read `config.NAME` directly (no `getattr` fallbacks).
- FPL rule facts come from `src/rules.py` (`OUTPUT_DC_THRESHOLD`, `OUTPUT_DC_POINTS`); never hardcode.
- `xpts_gw*` / `xpts_horizon` columns are not changed by this work (no backtest gate needed); only `wildcard_*` columns change.
- `build_chip_squad(..., preset=None)` must produce byte-identical squads to today for all existing callers; `tests/test_squad_draft*.py`, `tests/test_chip_advisor.py`, `tests/test_optimizer_free_hit.py` stay green.
- Work in a scratch worktree per repo (`git worktree add <scratchpad>/wc-v2-be -b feature/wildcard-v2 origin/master` for `FPL/`; `... -b feature/wildcard-v2 origin/main` for the frontend). Never switch branches in the main checkouts. One PR per repo; the user merges.
- User routes use `Depends(require_user)` from `src/auth.py`. Admin-only data writes use `require_admin`.
- CORS on the dev app is an explicit origin list; never `*`.
- Commit messages end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. A squad whose `entry_history.value` is missing (pre-season entry, or a payload from an older FPL shape) must fall back to the market-price budget and label it `source: "market"`, never 0. Test in Task 1.
2. A market where no midfielder meets the DC-probability floor under the bench budget must fall back to a DEF with `p_dc ≥ 0.5` and emit a note, not fail the build. Test in Task 4.
3. Pinned players that together break a cap (4 from one team, or 4 premiums in Balanced) must be reported as `pins_conflict` with the build still returned, not raise. Test in Task 5.
4. A player with fewer than 2 match-history rows must get trend 0 and injury prior 0 (not NaN, which would poison the sum). Test in Task 6.
5. Gems preset on a market with fewer than 6 sub-10% players that pass the gate must relax the ownership constraint and say so in `reason`, not return `ok: False`. Test in Task 5.

**Interfaces:**

Uses `fixture_difficulty.load_match_history()` columns `element, element_type, event, minutes, expected_goals, expected_assists, expected_goals_conceded, defensive_contribution`.
- `injury_prior.append_status_snapshot(bootstrap: dict, event_id: int, path: str) -> int` (rows written; **upsert** per `(event_id, element)`, last write wins, so a Friday flag overwrites Monday's `a`), CSV columns `event, element, status, chance`. Called from the refresh handler after `refresh_match_history`.
- `injury_prior.player_injury_prior(path: str) -> pd.DataFrame[element, p_miss, injury_flag]`: `p_miss = k/(n + SHRINK_GWS)` where `k` = GWs with status in `("i","d")`, `n` = GWs on file; `injury_flag = status now in ("i","d","s") or p_miss > 0.25`; missing file → empty frame (prior 0, flag False).
- `add_wildcard_scores` new columns: `wildcard_trend`, `wildcard_injury_mult` = `(1 − p_miss × INJURY_PRIOR_WEIGHT)`, `wildcard_upside` = `UPSIDE_WEIGHT × (ep_goals + ep_assists + ep_dc + ep_saves)` (position-neutral, GW1 components, zeros when absent), `wildcard_captaincy_bonus` (form term removed; × `preset["captaincy_mult"]` when preset), `wildcard_score = (weighted_xpts + dgw + captaincy + trend×TREND_WEIGHT×trend_mult + upside) × injury_mult`.
